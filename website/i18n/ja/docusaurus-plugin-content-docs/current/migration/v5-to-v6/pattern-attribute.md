# `pattern`属性

[`no-invalid-attr-value`](/docs/rules/no-invalid-attr-value)は、`<input pattern>`の値をHTML標準と同じようにコンパイルして検査します。`v`フラグつきのJavaScriptの正規表現として、まず値そのものを、次に`^(?:値)$`で包んだものをコンパイルします。ブラウザーはコンパイルできない`pattern`を無視するので、そのページが期待した検証は行われません。

v5は包んだ形だけを、フラグなしでコンパイルしていました。受け入れていた値が報告されるようになり、報告していた値が受け入れられるようになったものがあります。

## 報告されるようになったもの {#reported}

`v`フラグは、文字クラスの中のいくつかの文字を構文として読み、単独の`{`や`}`はエラーです。バックスラッシュでエスケープしてください。

| 値               | v5       | v6   | 書き換え   |
| ---------------- | -------- | ---- | ---------- |
| `[a-z-]+`        | 受け入れ | 報告 | `[a-z\-]+` |
| `[(]`            | 受け入れ | 報告 | `[\(]`     |
| `[a-]`           | 受け入れ | 報告 | `[a\-]`    |
| `a{`             | 受け入れ | 報告 | `a\{`      |
| `{`              | 受け入れ | 報告 | `\{`       |
| `\-`（`[]`の外） | 受け入れ | 報告 | `-`        |
| `a)\|(b`         | 受け入れ | 報告 | `a\)\|\(b` |

`a)|(b`は、包んだあと（`^(?:a)|(b)$`）でだけ有効です。標準は値そのものを先にコンパイルするので、ブラウザーはこれを無視します。

## 受け入れられるようになったもの {#accepted}

文字クラスの集合演算は`v`フラグの機能です。`[\p{L}--[a-z]]`はv5では報告されていましたが、v6では受け入れられます。

## `input[name]` {#name}

`<input name>`の値は、空文字列と`isindex`であってはなりません。行終端文字で始まる値は名前として有効で、受け入れられるようになりました。
