# test/isolated-env

Sandbox projects that install the built packages as `file:` dependencies and run them outside the workspace. The `file:` paths resolve only in the sibling-directory layout the `isolated-env` job of `.github/workflows/nightly.yml` builds; reproducing a failure locally needs that same layout.

- `pnpm-workspace.yaml` is the file pnpm reads for `overrides` and `allowBuilds`: when adding a local package to a sandbox's `dependencies`, add the matching `overrides` entry there (`packages/@markuplint/test-tools/src/isolated-env-manifests.spec.ts` fails until the two lists agree). Do not add a `pnpm` block to `package.json`; current pnpm ignores that block with only a warning (`The "pnpm" field in package.json is no longer read by pnpm`), so an override that exists only there does nothing: the `@markuplint/*` packages that `markuplint` depends on resolve to the registry instead of the local build, and the symptom is a single `config-error` violation (`Rule not found: <name>`) in place of the expected output.
- Several dependencies are deliberately `latest` (`@types/node`, `tsx`, `npm-run-all`) and pnpm is installed as `latest`, so a sandbox can break with no change on `dev`; Bun and Deno are `latest` in the nightly tests as well. Only the nightly tests (`.github/workflows/nightly.yml`) run the sandboxes, a night after the commit: a pull request that changes `test/isolated-env/**` or the dependencies is checked on Linux and Node.js 26 only, and the Issue that a failure opens is the first the sandboxes say of it. Triage before touching anything: compare with the previous green run of the nightly tests (`gh run list --workflow nightly.yml --branch dev`, then `gh run view <id> --json jobs`), delete the dependencies' cache and the build of that commit (`gh cache list --key dev-depends-modules-ubuntu-latest-node26` and `gh cache list --key prod-node26-<sha>`, then `gh cache delete <id>`: a run of the same commit finds the build in its cache and builds nothing, so the cache of the build has to go as well) and run the same commit again (`gh workflow run nightly.yml --ref dev -f force=true`); a failure that survives the cache rebuild is dependency drift, not a flake. When the drifted dependency is one the root `package.json` pins, pin the sandbox to that same version (`typescript` is pinned for this reason). Such a fix goes in a pull request of its own, with the two checks above on record in it.
